# T1.2 — Engine SRS (ts-fsrs + fallback 1-3-7-14-30)
## Why
SRS là core chung Anh/Trung; lịch 1-3-7-14-30 giữ daily routine hai ngôn ngữ.
Cần FSRS chuẩn + fallback khi chưa đủ dữ liệu ôn.
## Pre-conditions
- T1.1 xong (deck/card API + SQLite sẵn).
- Đã pin version ts-fsrs trong package.json.
## What to do
### Step 1 — Gói SRS frontend với fallback schedule
```python
# pseudo: srs scheduler
due = fsrs_next(card.history) if len(card.history) >= 3 else fallback([1,3,7,14,30])
store("card.due_at", value=due)
check("new card due == +1 day")
```
### Step 2 — API review ghi nhận kết quả ôn
```python
# pseudo: review endpoint
add_route("POST /api/review", handler=save_grade_update_due)
assert grade_flow([3,3,2]) == "due dates strictly increasing"
```
### Step 3 — Màn ôn cơ bản trên route Học
```python
# pseudo: review screen
render("ReviewCard(front, onGrade=[1..4])")
check("grading advances queue and persists via API")
```
